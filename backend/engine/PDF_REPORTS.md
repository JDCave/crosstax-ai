# 规则引擎 PDF 报告设计

## 契约与主流程

新增 `GET /api/v1/rule-engine/tasks/{task_id}/report`，成功返回 application/pdf 二进制附件。
主后端提交现有 tasks API，前端经主后端／业务网关轮询任务至 SUCCEEDED，再调用 report。
三态业务裁决均可导出；PENDING/RUNNING 返回 409 REPORT_NOT_READY，FAILED 返回 409 REPORT_TASK_FAILED，未知 404、到期 410，存储／密钥异常 503。
任务状态与接口不修改原契约，不新增数据库表或迁移。

报告只使用已加密保存的输入和完整结果，不重跑规则或调用百炼，不读取当前活动规则替换历史依据。
使用冻结规则版本、表单策略、构建标识、完成时间和输入指纹；校验结果版本与任务元数据不一致时拒绝导出。
摘要和原 JSON 的 SHA-256 同报告模板版本写入 PDF；响应提供 PDF 字节 SHA-256，便于接收方核对下载。
摘要用于一致性核验，不是电子签名，不承诺防止数据库管理员篡改。

报告明确标注“规则引擎校验报告”，不伪装成当前尚未实现的主 AuditSession 全流程最终审计报告。
主后端 `run_audit_pipeline()` 仍须汇总抽取、跨源研判及最终会话裁决；规则结果是其中一项输入。
如果前端所需“最终结果”指整条链路最终裁决，需主后端先实现并保存该契约，不能由导出服务猜测。

## 报告内容

- 标题、三态规则裁决、主体／税籍摘要与完成时间。
- task_id、session_id、原文 fingerprint（仅上游实际提供时）、规则版本/revision、表单策略和引擎指纹。
- 问题及严重度、来源、字段、证据引用；多税籍逐项状态、算法验证深度及官方出处。
- 逐项检查、已执行／未执行范围，AI 补正状态及原有建议（若有）。
- 原始 validation 请求与完整 ValidationResponse 的 JSON 附录，保留原字段及全部结果，避免漏掉少见字段；不附完整监管规则包或任务密钥。

动态文本全部转义，不执行 HTML、不访问上游提供的 URL、图片或文件路径。
字体随镜像打包并嵌入 PDF，离线生成中文，不依赖阿里云宿主机安装字体或在线字体服务。
字体不覆盖的字符以明确 Unicode 转义显示，完整 JSON 附录使用 ASCII Unicode 转义保存精确信息。

## 运行与保护

ReportLab 纯 Python 渲染，字体授权文件随库保存；pypdf 仅为测试依赖。
从 DB 读取后立即释放连接，CPU 渲染在线程池运行，不阻塞 FastAPI 事件循环。
每个 API 进程最多一个渲染，排队等待最多 1 秒，生成等待最多 15 秒；超时后后台线程若未结束仍占原许可，不放大并发。
限制源快照 2 MiB、最多 100 页、PDF 最多 8 MiB；超限明确 413 REPORT_TOO_LARGE，不截断并冒充完整报告。
渲染失败使用固定错误码，不回显表单或异常原文；日志不输出报告内容。
内存生成，无共享磁盘、OSS、Redis 或数据库连接扩容要求；不持久化 PDF。
保留时间沿用任务默认 24 小时；过期即拒绝，不允许绕过删除策略。提交与导出之间可能发生到期，渲染返回前再次检查。

## 阿里云与前端

使用同一项目镜像运行 API／Worker，包含字体和授权文件；RDS 数据库与任务密钥两端一致。
前端通过已有鉴权业务网关访问，网关校验任务所属会话，禁止直接匿名暴露内部任务／报告接口。
当前项目尚无用户认证或主会话归属实现；报告接口继承内部可信服务边界，不宣称增加 UUID 即提供授权。
响应 attachment 文件名只含固定前缀与 task UUID；Cache-Control=no-store、nosniff。
CORS 暴露 Content-Disposition、X-Report-SHA256、X-Report-Template-Version，前端使用 ArrayBuffer/Blob 下载。
反向代理保留二进制响应和下载头，超时应大于报告等待预算；报告不消耗规则验证的 30 秒审核预算。

## 验收与后续优化

真实 ASGI：提交 → Worker 完成 → 查询 JSON → 下载 PDF，检查三态结果、中文可提取、嵌入字体、逐项与范围、JSON 附录、分页与指纹一致。
验证未完成／失败／过期／未知、恶意标记转义、长字段分页、并发与取消、字节一致性、跨域下载头，以及无 AI/无当前规则刷新。
渲染代表性报告并逐页查看 PNG，确认不重叠、不截断。

优先后续优化：主会话授权与最终汇总契约 → 下载审计事件 → 大报告异步导出与私有 OSS 短期签名 URL → KMS 和报告签名／长期合规归档。
上述云服务与认证变化需要实际部署配置，不作为本次默默启用的依赖；文件 SHA-256 不能替代真实签名。
