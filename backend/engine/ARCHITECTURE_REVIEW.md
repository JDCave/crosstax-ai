# 同步后架构与规则接口核对（2026-11-08）

## 审查口径

依据上游 75fb627 的 architecture、ADR、新 CRS schema 与 feature spec，核对现有 HTTP 边界。
用户已明确：规则引擎对上游是黑盒，优先保证整个流程的输入与输出，存储实现不作为本轮迁移目标。
保留当前 DB 版本存储、全球目录和旧请求兼容，不修改 PM/设计文档中的既有裁定。
不把部分规则校验完成等同于整体抽取、跨源核验或法定条件全部满足。

## 发现与修复

| 流程要求 | 原实现差距 | 本次处理 |
| --- | --- | --- |
| D3 嵌套请求 | 只支持旧平铺及简化多税籍，完整新请求被 422 拒绝 | 增加 Structured FormData，接受原 schema 的全部字段和三种主体；单一 validate 路由自动识别，旧请求兼容 |
| 一文档一持有人 | 缺少文档元信息 | 根据上游 holders_declared 拒绝多持有人，独立 MULTI_HOLDER_DOCUMENT，停止后续字段校验；不以重复组计数 |
| 加密与结构树 | 无法表达受理／降级状态 | is_encrypted=true 不构成拒绝；结构树或指纹缺失输出复核问题；不读取原 PDF |
| 姓名、地址与可选字段 | 合并后无法检查姓／名／城市等 | 分别检查；可选出生地不判缺失，保留邮寄地址和排版异常；ISO 代码从外部参考表校验 |
| 日期 | 只支持 ISO | 接受 ISO 与 dd/mm/yyyy，内部规范为 ISO，等价日期的执行输入指纹相同；无效／未来签署日期阻断 |
| 多税籍 | 旧模式有 20 项技术上限 | 新结构不设任意税籍行数上限，实际受 1 MiB 传输上限约束；逐项返回结果 |
| 香港派生等值 | 未保留独立证件值 | 比较 HK TIN 与 HKID／BR 来源，报告两个字段路径、检查项及 TIN 轨迹；不回显号码 |
| POEM | 缺少独立语义 | 保留独立 basis；与实体实际管理地对照，不作为税籍替代或自动豁免，适用性复核 |
| 无 TIN | 仅旧字段命名 | 接收 no_tin_reason/reason_b_explanation；冲突与理由长度检查，C 的输入标记不能强行关闭人工复核 |
| 实体／控权人 | 无数据结构 | 保留分类子项、控权人姓名及逐实体类型矩阵；被动实体缺人、高管信息空缺、无所控实体等产生问题 |
| 声明与签署 | 只有 has_signature | 检查授权二选一、Capacity、明确声明以 POA 签署时的附件、日期与签名；未覆盖签署角色转复核 |
| 辅助 Agent | 大量新税籍可能超过动作上限导致错误 | 大输入不调用模型，固定补正最多 300 项；omitted_action_count 明确遗漏数，核心 issues 保留完整 |
| 升级影响分析 | 不接受新请求作为样本 | 支持新结构，同一次比较固定表单策略快照，并把 form_policy_id 绑定到报告哈希 |
| 容器运行 | 新规则文件与默认 Case 文件未进入镜像 | 复制规则和最小合成 Case；为非 root 用户准备工作目录／输出目录，不打包全部 PDF |

外部表单策略位于 rules/hk/form_policy.json，参数与角色名称映射属于项目校验策略。
policy_revision_date 表示项目策略修订日期，不限制所提供的业务日期，不是推定的税法生效日期，不包含未经核实的持股／罚则法律参数。
每次请求固定读取策略内容，execution.form_policy_id 绑定其规范化哈希；TIN rule_version_id 保持原有含义。
该文件通过代码部署维护，当前数据库候选包发布只管理 TIN 快照，不隐式修改此策略。
国家代码仅取自 pycountry 数据中的 alpha_2 标识，记录下载日期与源文件哈希，无新增运行依赖；
[参考源](https://raw.githubusercontent.com/pycountry/pycountry/main/src/pycountry/databases/iso3166-1.json)。代码合法不等于该地区 TIN 规则已覆盖。

## 调用与返回

公开 POST tasks + GET tasks/{task_id}，旧 validate 隐藏并保留。
任务只管理规则执行状态，主流程仍通过 run_audit_pipeline() 编排并维护 AuditSession／WebSocket。
持久化队列替代请求内后台线程，接口和 Worker 契约见 [异步设计](ASYNC_TASKS.md)。
推荐使用 assets/crs-templates/crs-structured-*-request.json 的个人、实体、控权人样例。
原有请求继续有效；这是为已开发调用方保留的兼容扩展，不将 source schema 的“旧实现不存在”前提带入运行环境。
基于 document/name/addresses/declaration 等新字段识别新结构；未知字段仍被拒绝。

返回使用原有 verdict/issues/residence_results/check_items/review_scope/execution，新增 form_policy_id 和补正截断计数。

未核实范围不是已通过结果，模型补正也不改变裁决。
